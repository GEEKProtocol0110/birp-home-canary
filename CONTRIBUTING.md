# Contributing to BIRP

Start with docs/STATUS.md and the control specification. Describe the observed problem, proposed change, and evidence. Label simulated data and conceptual illustrations clearly.

Keep sensor thresholds configurable and record the basis for selected values. Preserve explicit unknown/fault states. Never add a reassuring calm output for missing measurements. Changes to mechanical motion need documented travel and reference limits.

For website changes, preserve keyboard access, mobile layout, reduced-motion support, and prototype labeling. Include only claims supported by project evidence.

A license has not yet been selected. Discuss substantial external contributions with the project owner before submitting them.
